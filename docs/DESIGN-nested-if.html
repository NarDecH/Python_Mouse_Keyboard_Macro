🧠 DESIGN — เงื่อนไขเชิงซ้อน (Nested If) และลูปย่อย

ข้อเสนอแบบเปิด — ยังไม่ลงโค้ด · ร่วมคุยได้ที่ Issues

1. โจทย์

ปัจจุบัน (v2.6.0 — หลังชุด N1) ทุกเงื่อนไขทำงานแบบ "ข้ามแถวตรง ๆ" (+ ผสมเงื่อนไขย่อยด้วย && ได้แล้วทุกชนิด):

แถว 1  If Image (btn.png)  Repeat = 5   ← ถ้าไม่เจอ ข้ามแถว 2–6
แถว 2  ...งานเมื่อเจอภาพ
...
แถว 6  Else If Image       Repeat = 3   ← ถ้ากลุ่ม A เล่นแล้ว ข้ามกลุ่ม B

จุดแข็ง: อ่านง่าย ตรวจสอบง่าย ไม่มี state ซ้อน — ข้อจำกัดที่ผู้ใช้ถามบ่อย:

  1. เงื่อนไขซ้อนเงื่อนไข — "ถ้าภาพเจอ และ สีจุดถูก → ทำ A, ถ้าภาพเจอแต่สีผิด → ทำ B" (ตอนนี้ต้องแตกเป็น If หลายลำดับ สคริปต์ยาวและเดายาก)
  2. ลูปย่อย — "วนแถว 5–9 จนกว่าภาพจะเจอ (สูงสุด 10 รอบ)" — ปัจจุบันต้องวนทั้งสคริปต์ หรือ Repeat ของแถว (ทำซ้ำแถวเดียว ไม่ใช่ช่วงแถว)

2. เป้าหมาย / เงื่อนไขยอมรับ

  • ✅ กฎเดียวคงอยู่: แถวเงื่อนไขที่ "ไม่จริง" แล้วข้าม = ค่า Repeat เสมอ — สคริปต์เดิมต้องเล่นผลเหมือนเดิม (backward compatible 100%)
  • ✅ เขียนในตารางเดิม ไม่แนะนำรูปแบบไฟล์สคริปต์ใหม่ (ยังเป็น JSON รายแถวเท่าเดิม)
  • ✅ STOP ต้องหยุดได้ทุกชั้นของลูปย่อย (หลักการข้อ 1 ของโปรเจกต์)
  • ✅ ผ่านเทสต์ทั้ง GUI/CLI ด้วย ActionRunner แหล่งเดียว (ห้าม do_step สองชุด)
  • ✅ --validate ตรวจโครงสร้างซ้อนได้ (บล็อกที่ไม่ปิด = รายงานแถวที่ผิด)

3. แนวทางที่พิจารณา

แนะนำ ทางเลือก A — บล็อกที่มีเครื่องหมายเปิด/ปิด

เพิ่ม Action คู่เปิด-ปิด คล้ายหัวข้อ Section ที่มีอยู่แล้ว:

แถว 1  🔷 Block Start (If Image btn.png)   ← เปิดบล็อก เงื่อนไขไม่จริง = กระโดดไป Block End
แถว 2  ...ทำ A
แถว 3  ...ทำ A
แถว 4  🔷 Block End                         ← ปิดบล็อก (ป้ายเท่านั้น ไม่เล่น)
  • ซ้อนได้ตามธรรมชาติ — Block Start ข้างในอีก Block Start ได้ (runner เก็บ stack)
  • เงื่อนไขไม่จริง = กระโดดข้ามไป Block End ที่จับคู่กัน (นับวงเล็บ) — ไม่ต้องนับแถวเอง แก้/แทรก/ลบแถวข้างในไม่มีผล
  • ลูปย่อย: Additional เพิ่มได้ เช่น until img.png หรือ max 10 = ถึง Block End แล้วกระโดดกลับแถวเปิดบล็อก วนจนเงื่อนไขจริง/ครบ max
  • GUI: สีแถวหมวดใหม่ + ย่อ/ขยายบล็อกต่อยอดกลไก Section (_section_stash)
  • CLI/--validate: นับเครื่องหมายเปิด/ปิดให้ครบก่อนเล่น (ไม่ครบ = error รายแถว)
⚠️ ระวังผู้ใช้ลบ Block End ทิ้ง — ทางแก้: ลบไม่ครบคู่ → --validate เตือนก่อนเล่น (คล้าย _on_del_cleanup ของกลุ่มย่อ)

ทางเลือก B — เงื่อนไขรวม (AND/OR) ในแถวเดิม

ขยาย If Image/If Pixel ฯลฯ ให้ Additional ต่อท้าย && / || ได้ เช่น btn.png && 300,300 #ffffff

  • ข้อดี: ไม่เพิ่ม Action ใหม่ กฎ Repeat เดิมใช้ต่อได้ทันที
  • ข้อเสีย: แก้ปัญหาข้อ 1 เท่านั้น — ไม่ได้ลูปย่อย · Additional ยาวจนอ่านยาก
  • สรุป: เหมาะเป็นขั้นแรก (ริสก์ต่ำ) ก่อนลงทางเลือก A

ทางเลือก C — โหมดสคริปต์ล้วน (if/while จริง)

เพิ่ม Action "Python Block" รันโค้ดผู้ใช้ — ❌ ขัดหลักการ "ไม่มีโค้ด" + ความปลอดภัย (สคริปต์แชร์กันอันตรายขึ้น) — ตัดทิ้ง

4. แผนที่เสนอ (2 ชุดย่อย)

ชุดขอบเขตจุดเสี่ยง/เทสต์สำคัญ
N1 — AND ✅ v2.5.4 · OR || ✅ v2.19.0 parser ใน engine (split_condition_and + parser เดิม) รองรับ && · evaluate_condition ประเมินแบบ short-circuit — ครบ If Image/If Pixel/If Variable/If Loop/If Time + --validate + เดโม่ examples/11 เทสต์ parser (แตก/เว้นวรรค/พัง) + เล่นจริง GUI/CLI
N2 — Block Start/End Action ใหม่ 2 ตัว + ROW_STYLE หมวดใหม่ · runner เก็บ stack (แถวเปิด, จำนวนรอบ) · ย่อ/ขยายบล็อกต่อยอด _section_stash · --validate ตรวจคู่เปิด/ปิด + จำกัด depth ซ้อน 2 ชั้น · ลูปย่อย + If ข้างใน · STOP กลางลูปย่อย · ลบ End แล้ว validate เตือน
สิ่งที่ห้ามลืม (บทเรียนเดิมของโปรเจกต์): แถวเงื่อนไขใหม่ต้อง break/continue ก่อน do_step/ดีเลย์เสมอ · ข้อความใหม่ใส่ TR ทั้ง th/en + เอกสาร .md/.html พร้อมกัน · dialog ใหม่ต้องมีเทสต์ "เปิด + ใช้งานจริง" อย่างน้อย 1 ตัว

6. OR (||) — ✅ เสร็จ v2.19.0 (สรุป)

หัวข้อนี้พูดถึง v2.19 เท่านั้น — ชุดถัดไป N3 (รอจนจริง/วนแถวเดียวจนจริง/ If Changed) อยู่ milestone v2.20

เงื่อนไขทุกชนิดคั่น || ได้ (If Variable / If Loop / If Time / If Pixel Color / If Image / Block Start if/until) — engine split_condition_or() แตกสายระดับบนสุด (โทเคน >ชื่อ ตัดก่อนแตก) แล้วแต่ละสายแตก && ต่อ (&& แน่นกว่า || ตามมาตรฐาน) · short-circuit: สายใดจริงก่อน = จริงทั้งนิพจน์ ไม่ประเมินสายที่เหลือ · ทุกสายไม่จริง = ข้าม N แถว (กฎเหล็กเดิม)

  • โทเคน >ชื่อ เก็บผลรวม (1 = มีสายใดจริง / 0 = ทุกสายไม่จริง)
  • ครบทุกเส้นทาง: evaluate_condition (IF_VAR/IF_LOOP/IF_TIME) · runner.execute (IF_IMAGE/IF_PIXEL — ค้นภาพทีละสาย + {img_x}/{img_y}) · evaluate_block_condition (สายพัง None ไม่กลืนจริง) · validate_rows รายงาน "สายที่ N (||)" · row_tag/ค้นหา/hint
  • .ahk สองทิศ — export/import if (a || b) และบล็อก if (a) { … } roundtrip ครบ (สายแปลไม่ได้ = comment ทั้งบล็อก)
  • เทสต์ TestOrConditions 20 ตัว + TestExample19OrConditions — รวม 589 unit + 20 E2E = 609 · เดโม่ examples/19_or_conditions.json
  • รายละเอียดฉบับเต็ม + สถานะรายจุด (กับหมายเลขบรรทัด): ดูหัวข้อ 6 ใน DESIGN-nested-if.md (ฉบับ .md สรุปเชิงลึกกว่า)
