## บทที่ 1 — ติดตั้งและเริ่มต้น

### 1.1 ติดตั้ง

**แบบ .exe (ง่ายสุด):**
ดาวน์โหลด `AutoMouseMacro.exe` จากหน้า [Releases](https://github.com/NarDecH/Python_Mouse_Keyboard_Macro/releases) แล้วดับเบิลคลิก — ไม่ต้องติดตั้ง Python

**แบบรันจากซอร์ส:**

```bash
py -m pip install -r requirements.txt   # pynput (+ opencv-python Pillow สำหรับ Image Click)
py auto_macro.py                        # หรือดับเบิลคลิก run.bat
```

> เครื่องที่ `python` ไม่ทำงาน (Windows Store stub) ให้ใช้ `py` แทนเสมอ

### 1.2 รู้จักหน้าจอ

| ส่วน | หน้าที่ |
|---|---|
| แถวเมนูบนสุด | Save / Load / Settings / About / Help / Exit |
| แถบ "โปรไฟล์" | สลับชุดสคริปต์ (เก็บหลายชุดได้) + ปุ่ม ⏰ เล่นอัตโนมัติตามเวลา |
| ตารางกลาง | สคริปต์ของคุณ — 1 แถว = 1 คำสั่ง |
| แถวปุ่ม ＋/－/▲▼ | จัดการแถว (เพิ่ม/ลบ/เลื่อน/ล้าง) + 📸 จับภาพ |
| ปุ่ม START/STOP/REPEAT/RECORD | ควบคุมการทำงาน + ตัวเลือกความเร็ว/รอบ |
| แถบสถานะล่าง | Progress, พิกัดเมาส์สด, คีย์ที่กดล่าสุด, ข้อความสถานะ |

### 1.3 คีย์ลัด (กดได้แม้ไม่โฟกัสหน้าต่าง)

`F6` เล่น • `F8` หยุด • `F9` บันทึก • `F10` วนไม่จำกัด • `Delete` ลบแถวที่เลือก

## บทที่ 2 — อัดสคริปต์แรกใน 60 วินาที

1. กด **RECORD** (หรือ F9) — สถานะเปลี่ยนเป็น "กำลังบันทึก"
2. คลิกที่จอ 2–3 จุด, เลื่อนล้อเมาส์, พิมพ์อะไรสักหน่อย
3. กด **F9** อีกครั้ง — ทุกเหตุการณ์ถูกจดลงตารางพร้อมจังหวะเวลา (Secs)
4. กด **F6 (START)** → โปรแกรมเล่นซ้ำทุกอย่างที่เพิ่งทำ
5. ลองกด **REPEAT** ให้วนตลอด → หยุดด้วย **F8** (หยุดทันที ไม่ต้องรอจบแถว)

> 💡 ช่อง ☑ หน้าแถว = เปิด/ปิดแถวนั้น (แถวที่ ☐ จะถูกข้ามตอนเล่น)

## บทที่ 3 — เข้าใจทุกคอลัมน์

| คอลัมน์ | ความหมาย | เกร็ด |
|---|---|---|
| ☑ | เปิด/ปิดแถว | คลิกเพื่อสลับ |
| # | ลำดับ | จัดการอัตโนมัติ |
| X, Y | พิกัดเมาส์ (Action เมาส์) หรือระยะ Offset (Move by Offset) | **ดับเบิลคลิก = จับพิกัดหลังนับ 3 วิ** |
| Button/Action | ชนิดคำสั่ง | ดับเบิลคลิกเพื่อเลือกจาก dropdown |
| Additional | ค่าเสริมตาม Action (ดูตารางด้านล่าง) | ดับเบิลคลิกเพื่อแก้ |
| Mins / Secs | ดีเลย์ **ก่อน**ทำแถวนี้ (นาที/วินาที) | Secs ใส่ `1-3` = สุ่ม 1–3 วิ |
| Repeat | ทำแถวนี้ซ้ำกี่ครั้ง | เช่น Enter 3 ครั้ง = Repeat 3 |

### ค่า Additional ตาม Action

| Action | Additional | ตัวอย่าง |
|---|---|---|
| Tap/Press/Release Key | ชื่อคีย์: `a` `space` `enter` `esc` `ctrl` `f5` `pgup` หรือเลข vk `27` | `enter` |
| Scroll Up/Down | จำนวนจังหวะ | `3` |
| Type Text | ข้อความ (รองรับไทย) | `สวัสดี world` |
| Launch App | โปรแกรม/URL | `notepad.exe`, `https://...` |
| Image Click / Wait for Image | ไฟล์.png หรือ `ไฟล์.png@x,y,w,h#threshold` | `btn.png@100,200,300,80#90` |
| If Image / Else If Image (v1.17+) | ไฟล์.png (เหมือน Image Click) — Repeat มีความหมายพิเศษ | `btn.png` (Repeat = แถวที่ข้าม/แบ่งกลุ่ม) |
| If Image แบบรอซ้ำ (v2.4) | เดิม + ต่อท้าย `Ns` = ตรวจซ้ำก่อนตัดสิน | `img.png 5s` = รอสูงสุด 5 วิ |
| Wait for Pixel Color (v1.18) | `x,y #RRGGBB` (หน่วงก่อนตรวจใส่ใน Secs) | `300,300 #ffffff` |
| If Pixel Color (v2.5) | `x,y #RRGGBB` ต่อท้าย `Ns` ได้ — ตรงเล่นต่อ ไม่ตรงข้าม N แถว | `300,300 #ffffff` |
| Read Pixel Color (v2.5) | `ชื่อ x,y` — อ่านสีจุดเก็บเป็น `{ชื่อ}` | `สีจอ 300,300` |
| If Variable (v2.5) | `ชื่อ ตัวดำเนินการ ค่า` (`> >= < <= = ~`) — `~` = มีคำนี้ในข้อความ | `รอบ > 5` |
| เงื่อนไขรวม && (v2.6.0) | ต่อเงื่อนไขด้วย `&&` — ทุกเงื่อนไขต้องจริงจึงเล่นต่อ | `img.png && 300,300 #ffffff` |
| Move Mouse by Offset | ระยะเปลี่ยนแปลง (ใส่ใน X,Y) | X=50 Y=-20 |
| อื่น ๆ (Click/Down/Up/Move/Save/Restore/Beep) | ไม่ต้องใส่ | — |

## บทที่ 4 — Action ทั้งหมดและเมื่อไหร่ควรใช้

**เมาส์พื้นฐาน:** Left/Right/Middle Click, Down, Up (Down→Up = ลาก drag)
**คลิกพิเศษ:** Double Click, Ctrl+Click, Shift+Click, Alt+Click, Ctrl+Right Click
**การเคลื่อนที่:** Move Mouse (ไปพิกัด), Move Mouse by Offset (ขยับสัมพัทธ์)
**จดจำตำแหน่ง:** Save Cursor → … → Restore Cursor (คู่ต้องใช้ด้วยกัน)
**คีย์บอร์ด:** Tap/Press/Release Key, Type Text
**ภายนอก:** Launch App (เปิดโปรแกรม/เว็บ)
**อัจฉริยะ:** Image Click (หาภาพแล้วคลิก), Wait for Image (รอภาพก่อนทำต่อ),
Wait for Pixel Color (v1.18 — รอจุดสีก่อนทำต่อ)
**เงื่อนไข (v1.17+):** If Image (ไม่เจอ → ข้าม N แถว), Else If Image (สองทาง A/B — ดูบทที่ 5A),
If Loop / If Time (นับรอบ/เวลา — ดูบทที่ 5B), If Pixel Color (สีจุด), If Variable (เทียบตัวแปร),
หัวข้อ Section (จัดระเบียบตาราง) — กฎเดียวกันทุกตัว: **Repeat = จำนวนแถวที่ข้ามเมื่อเงื่อนไขไม่จริง**
(v2.14.1: การข้ามกินเฉพาะแถวลำดับตรง — หัวข้อ/Block Start/End ไม่กิน skip และการกระโดดของบล็อกยกเลิก skip ค้างเสมอ)
**ตัวแปร:** Set Variable (รวม `rand a-b` — ดูบทที่ 12), Read Pixel Color, Image Click ตั้ง `{img_x}/{img_y}` ให้เอง
**เสียง:** Beep (จุดเช็คว่าสคริปต์ถึงไหน)

**หลักคิด: พิกัด vs ภาพ**
- ปุ่มอยู่ตำแหน่งเดิมเสมอ → ใช้พิกัด X,Y (เร็ว)
- หน้าต่างเลื่อนได้ → ใช้ Image Click (ทนทานกว่า)

## บทที่ 5 — Image Click + Search Area + Threshold

> 🎥 **ดูคลิปสอนก่อนได้:** [docs/images/tutorial_image.mp4](images/tutorial_image.mp4) —
> สาธิตจริงตั้งแต่จับภาพ → ตั้งค่า → เล่นคลิก → If Image A/B → Wait for Image

### 5.1 เตรียมภาพ
กดปุ่ม **📸 จับภาพ (ลากกรอบบนจอ)** → โปรแกรมหดตัวเอง → ลากครอบปุ่ม/วัตถุที่ต้องการ → ตั้งชื่อไฟล์ (เช่น `play.png`) — เซฟไว้ที่โฟลเดอร์โปรแกรม

### 5.2 ใช้งาน
เพิ่มแถว **Image Click** → Additional ใส่:

| รูปแบบ | ความหมาย |
|---|---|
| `play.png` | ค้นทั้งจอ, threshold 80% |
| `play.png@100,200,500,300` | ค้นเฉพาะกรอบ (100,200) กว้าง 500 × สูง 300 — **เร็วกว่าและแม่นกว่า** |
| `play.png@100,200,500,300#90` | เดิม + ต้องมั่นใจ 90% ขึ้นไป |
| `play.png#65` | ทั้งจอ, ผ่อนเป็น 65% (ภาพเปลี่ยนบ่อย) |

> 💡 Search Area คือเครื่องมือที่ทำให้ Image Click ใช้งานจริงได้ — กรอบแคบ = เร็วขึ้นหลายเท่า + ไม่คลิกภาพเดียวกันที่อยู่มุมอื่น
> threshold สูง (90–95) = เข้มงวด, ต่ำ (60–70) = ทนสี/แสงเปลี่ยน แต่เสี่ยงคลิกผิด

## บทที่ 5A — เงื่อนไข: If Image และ Else If Image (v1.17+)

ทำให้สคริปต์**ตัดสินใจเองได้** โดยไม่ต้องเขียนโค้ด:

### If Image — ไม่เจอแล้วข้าม
- Additional = ไฟล์ .png (ใช้ Search Area/threshold ได้เหมือน Image Click)
- **ภาพเจอ** → เล่นแถวถัดไปตามปกติ
- **ภาพไม่เจอ** → ข้ามแถวถัดไป **N แถว** (N = ค่าคอลัมน์ **Repeat** ของแถว If Image)
- เหมาะกับ: "ถ้าโฆษณาเด้ง → กดปิด, ไม่เด้ง → เล่นต่อ" (Repeat = จำนวนแถวปิดโฆษณา)

### Else If Image — เงื่อนไขสองทาง (v1.18)
วาง**หลังกลุ่ม A** เพื่อแบ่งสคริปต์เป็นสองทาง:

```text
แถว 1  If Image (btn.png)      ← เช็คเงื่อนไข
แถว 2  ...กลุ่ม A (เล่นเมื่อเจอภาพ)
แถว 3  ...กลุ่ม A
แถว 4  Else If Image (btn.png) Repeat = 2   ← Repeat = จำนวนแถวกลุ่ม B ที่จะข้าม
แถว 5  ...กลุ่ม B (เล่นเมื่อไม่เจอภาพ)
แถว 6  ...กลุ่ม B
```

- If Image **เจอ** → เล่นกลุ่ม A หมด → แถว Else **ข้ามกลุ่ม B** (จำนวน = Repeat ของ Else)
- If Image **ไม่เจอ** → กลุ่ม A ถูกข้าม (ตาม Repeat ของ If) → แถว Else **เล่นกลุ่ม B ต่อ**
- ⚠️ Else If Image ใช้ผลของ If Image **ล่าสุด** เสมอ — วางคู่กันให้ถูกลำดับ

### Wait for Pixel Color — รอจุดสี (v1.18)
- Additional: `x,y #RRGGBB` เช่น `300,300 #ffffff` — รอจนจุด (300,300) มีสีใกล้เคียงขาว
- หน่วงก่อนเริ่มตรวจใส่ใน Secs (รองรับ `1-3` สุ่มได้) · รอนานสุด 30 วิ แล้วข้ามต่อ
- เหมาะกับ: รอ progress bar เต็ม, รอไฟสถานะเขียว, รอปุ่มเปลี่ยนสี

### เงื่อนไขรวม && — หลายเงื่อนไขพร้อมกัน (v2.6.0)

ต่อท้าย Additional ด้วย `&&` ได้ทุกเงื่อนไขหลัก — **ทุกเงื่อนไขต้องจริง** จึงเล่นต่อ:

```text
If Image        img.png && 300,300 #ffffff && n > 5
                ← ภาพเจอ และ สีจุดตรง และ ตัวแปร n > 5 จึงเล่นแถวถัดไป
If Pixel Color  300,300 #ffffff && 400,400 #000000
                ← จุดสีทั้งสองจุดตรงหมด (ใช้ retry 5s ร่วมได้)
If Variable     n > 5 && code = A-1
                ← เทียบหลายตัวแปรพร้อมกัน
```

- ชิ้นใดไม่จริง = ข้าม N แถว (N = Repeat — กฎเดียวกับเงื่อนไขเดี่ยว)
- ใช้ timeout `Ns` ร่วมได้ เช่น `img.png 5s && 300,300 #ffffff` (ตรวจซ้ำจนครบ 5 วิก่อนตัดสิน)
- ตรวจสคริปต์ด้วย `--validate` — เข้าใจ && และรายงานชิ้นย่อยที่พังให้ครบ

### แบบฝึกหัด (ทำตามได้จริง — ไม่คลิก ไม่กดคีย์)
1. เปิด `examples/07_conditions.json` ผ่านเมนู 📂 Load (หรือ `py auto_macro.py examples/07_conditions.json`)
2. กด ▶ START — เดาก่อนว่าจะไปกลุ่ม A หรือ B? (เฉลย: ขึ้นกับว่า `target.png` อยู่บนจอหรือไม่)
3. ลอง**ซ่อนหน้าต่างที่มี target.png** แล้วเล่นใหม่ — เส้นทางต้องเปลี่ยน
4. แก้ Repeat ของ Else เป็น 3 แล้วเพิ่มแถวกลุ่ม B — สังเกตจำนวนแถวที่ถูกข้าม
5. เปิด 📊 Stats — ดูว่า Action ไหนกินเวลารวมมากสุด (v1.18)
6. (v2.6.0) ลองแก้เป็น `target.png && 100,100 #000000` แล้วเปลี่ยนสีที่จุดนั้น — เห็น AND ตัดสิน

### Block Start / Block End — บล็อกเงื่อนไขและลูปย่อย (v2.6.0)

Action คู่ `🔷 Block Start` → `🔷 Block End` ครอบแถวกลุ่มหนึ่ง (ซ้อนกันได้ 8 ชั้น) —
เขียนคำสั่งที่ช่อง Additional ของ **Block Start**:

```text
(เว้นว่าง)            เปิดบล็อกเสมอ — ใช้จัดระเบียบ/วางแผนขยายภายหลัง
if img.png            เงื่อนไขไม่จริง → ข้ามทั้งบล็อก (หา End คู่ด้วยการนับวงเล็บ)
if n > 5              เงื่อนไขตัวแปร/สีจุด/ภาพ + && ผสมได้ เช่น if img.png && n > 5
until img.png         ลูปย่อย: จบถึง End แล้ววนกลับเล่นซ้ำจนเจอภาพ (สูงสุด 1000 รอบ)
until n >= 5 max 20   วนจน n >= 5 แต่ไม่เกิน 20 รอบ — ครบ max แล้วออกจากลูปเอง
max 10                ไม่มีเงื่อนไข — วนเนื้อใน 10 รอบ
```

- ต่างจาก If Image: **ไม่ต้องนับแถว** — ข้าม/วนกลับตามคู่ Start/End แก้แถวข้างในได้อิสระ
- เนื้อในบล็อกใช้ If Loop/Set Variable ตั้งตัวแปรแล้วใช้ `until n >= 5` เป็นตัวนับรอบได้
- `--validate` ตรวจคู่เปิด/ปิด บล็อกซ้อนลึกเกิน 8 ชั้น และรูปแบบ Additional ให้ครบก่อนเล่น
- ลองเล่นเดโม่: `py auto_macro.py examples/12_blocks.json` (if ข้ามบล็อก / until นับ 1-5 /
  บล็อกซ้อน 2 ชั้น — ไม่คลิก ปลอดภัย)

## บทที่ 5B — เงื่อนไขนับรอบ/เวลา และหัวข้อ Section (v1.21)

### If Loop — รอบที่ N ขึ้นไปให้ข้าม
- Additional = **เลขรอบ** เช่น `3` → รอบที่ 3, 4, 5, ... แถวถัดไปจะถูกข้าม
- จำนวนแถวที่ข้าม = คอลัมน์ **Repeat** ของแถว If Loop (กฎเดียวกับ If Image)
- เหมาะกับ: "**รอบแรก setup** (เปิดโปรแกรม/ล็อกอิน) **รอบถัดไปข้าม**" — วาง If Loop `2`
  Repeat = จำนวนแถว setup

```text
รอบที่ 1:  Beep → If Loop 3 (ยังไม่ถึง → เล่นต่อ) → Beep#2 → Beep#3
รอบที่ 3:  Beep → If Loop 3 (ถึงแล้ว → ข้าม 2 แถว) → Beep#3
```

### If Time — ผ่านเวลากำหนดแล้วให้ข้าม
- Additional = `HH:MM` เช่น `22:30` → ถ้าตอนเล่นเลย 22:30 ของวันนี้แล้ว ข้ามแถวถัดไป N แถว (Repeat)
- ยังไม่ถึงเวลา → เล่นต่อตามปกติ (เงื่อนไขทำงานเงียบ ๆ ไม่หน่วง)
- เหมาะกับ: "หลัง 22:30 งานค้างคืนให้หยุดทำ", "ก่อนเที่ยงใช้เส้นทาง A หลังเที่ยงข้าม"

### หัวข้อ Section — จัดระเบียบสคริปต์ยาว
- คลิกขวาที่แถว → **🗂️ เปลี่ยนเป็นหัวข้อ Section** (หรือ "เพิ่มหัวข้อ Section" แทรกแถวใหม่)
- แถวหัวข้อเป็น**ป้ายชื่อกลุ่ม**พื้นสีเทาเข้ม: ไม่ถูกเล่น ไม่นับเลขลำดับ (#) ไม่หน่วง —
  เปลี่ยนข้อความได้ตามปกติด้วยดับเบิลคลิกช่อง Additional
- สลับกลับเป็นแถวธรรมดา (Left Click) ได้ด้วยเมนูขวาอีกครั้ง

### แบบฝึกหัด (ทำตามได้จริง — ปลอดภัย เล่นจบเอง)
1. รัน `py auto_macro.py examples/10_conditions_v21.json --loops 3` (หรือ Load ใน GUI แล้วตั้งช่อง รอบ = 3)
2. สังเกต: รอบ 1–2 ได้ยิน Beep ครบ / **รอบ 3 แถว "รอบ 3 ขึ้นไป..." หายไป** — นั่นคือ If Loop ทำงาน
3. ดูหัวข้อ "⬛ หัวข้อ กลุ่ม A/B" ในตาราง — ไม่มีเลข # และไม่ถูกเล่น
4. แก้ If Time เป็นเวลา **1 นาทีถัดจากตอนนี้** แล้วเล่นใหม่ — แถวถัดไปถูกข้ามทันที (ผ่านเวลาแล้ว)
   💡 ใช้ปุ่ม **🕐 เวลานี้ (+15 นาที)** บนแถบเครื่องมือเติมเวลาให้แถวที่เลือกอัตโนมัติ (v1.22)
5. ลองคลิกขวาแถวไหนก็ได้ → เปลี่ยนเป็นหัวข้อ → กด START — สังเกตว่าแถวนั้นไม่ถูกเล่น

### ย่อ/ขยายกลุ่ม + สีแถว (v1.22)
- **ย่อกลุ่ม:** คลิกขวาที่หัวข้อ → **📁 ย่อกลุ่มนี้** — แถวสมาชิกหายจากจอ หัวข้อขึ้นป้าย `(ย่อ N แถว)`
  **แต่แถวซ่อนยังถูกเล่นตามปกติทุกอย่าง** (รวม Save/Load) — กดซ้ำ **📂 ขยายกลุ่มนี้** ได้ลำดับเดิมเป๊ะ
- ลบหัวข้อที่ย่ออยู่ = โปรแกรมขยายคืนก่อนแล้วจึงลบ (แถวไม่หาย) · ย้ายกลุ่ม = เลือกหัวข้อแล้วกด ▲▼
- **สีแถวช่วยอ่าน:** เหลืองอ่อน = เงื่อนไข, ม่วงอ่อน = คีย์บอร์ด, ฟ้าอ่อน = Action พิเศษ,
  ขาว-ฟ้าสลับ = แถวเมาส์ — สีเป็นแค่การจัดระเบียบ ไม่มีผลกับการเล่น

## บทที่ 7 — โปรไฟล์ และ เล่นอัตโนมัติตามเวลา

**โปรไฟล์:** แถบใต้เมนู → ＋ สร้าง "เกมA", "งานรายวัน" ฯลฯ — สลับแล้วตารางเปลี่ยนตาม (เซฟชุดเดิมอัตโนมัติ) เก็บใน `macro_profiles.json`

## บทที่ 10 — สำรอง/ย้ายเครื่อง และดูสถิติ

### 10.1 Backup อัตโนมัติ (v1.13+)

ปิดโปรแกรมทุกครั้ง โปรแกรมจะสำรองงาน + โปรไฟล์ทุกชุด + การตั้งค่าลง
`backups/backup_วันที่_เวลา.json` และตัดไฟล์เก่าให้เหลือย้อนหลัง **7 วัน** (ปรับได้ใน Settings)
เอาไว้กู้คืนเมื่อแก้สคริปต์พัก หรือย้ายเครื่อง — เปิด/ปิดระบบนี้ได้ใน Settings

### 10.2 Export / Import (สำรองแบบควบคุมเอง)

Settings → **⬆️ Export การตั้งค่า** = ไฟล์เดียวจบ (งาน + โปรไฟล์ + ตั้งค่า)
เอาไปเปิดที่เครื่องอื่นด้วย **⬇️ Import การตั้งค่า** — โปรแกรมจะโชว์พรีวิวและถามยืนยันก่อนเสมอ

### 10.3 ดูสถิติ + กราฟ + สถิติราย Action (v1.18)

เมนู **📊 Stats** — สรุปจาก log ทุกวัน: เริ่มเล่นกี่ครั้ง, ถูกหยุดกี่ครั้ง,
watchdog รีสตาร์ตกี่ครั้ง, แถวไหนช้าสุด, พร้อม**กราฟแท่ง 14 วันล่าสุด**
เห็นแนวโน้มการใช้งานได้ทันที (เขียวเข้ม = เริ่มเล่น, เขียวอ่อน = เหตุการณ์)
และตั้งแต่ v1.18 มี**⏱ Action ที่ใช้เวลารวมมากสุด (5 อันดับ)** —
ชี้ว่าสคริปต์เสียเวลาส่วนใหญ่ไปกับ Action ไหน เพื่อหา bottleneck ปรับปรุงได้ทันที
(เช่น Image Click ช้า → ใส่ Search Area ให้แคบลง)

### 10.4 ตรวจว่าระบบพร้อมจริง

Settings → **🧪 ทดสอบระบบจริง** = เมาส์จะขยับเป็นสามเหลี่ยมแล้วคืนจุดเดิม + บี๊บ 2 ครั้ง
ถ้าเมาส์ไม่ขยับหรือไม่ได้ยินเสียง = มีปัญหาจริง (ลอง Run as Administrator)
ส่วนหัว Settings จะแสดงผล self-check ตอนเปิดโปรแกรม (pynput/hotkey/OpenCV/admin)

### 10.5 สลับภาษาโปรแกรม (v1.14+)

Settings → **ภาษา (Language)** เลือก ไทย / English — ปุ่มหลักและข้อความสถานะเปลี่ยนทันที

## บทที่ 12 — ตัวแปรและคลิปบอร์ด (v1.19+)

### 12.1 ตัวแปรในสคริปต์ (Set Variable)

เพิ่ม Action **Set Variable** แล้วพิมพ์ในช่อง Additional:

| พิมพ์ | ความหมาย |
|---|---|
| `รอบ = 1` | ตั้งค่า (ข้อความหรือตัวเลขก็ได้) |
| `รอบ += 1` | บวกเพิ่ม (ตัวเลข — ตัวแปรใหม่เริ่มที่ 0) |
| `รอบ -= 1` | ลดลง |

เรียกใช้ด้วย `{ชื่อตัวแปร}` ได้ใน**ทุกช่อง** — X, Y, Additional, Mins, Secs, Repeat
เช่น แถว Beep วาง Secs = `{รอบ}` → ดีเลย์ตามค่าตัวแปร, แถว Type Text วาง
Additional = `ทำไปแล้ว {รอบ} รอบ` → พิมพ์ตัวเลขจริงออกมา

```bash
py auto_macro.py examples/08_variables.json     # เดโม่ทำตาม (ไม่คลิก ปลอดภัย)
```

ข้อควรรู้:
- ชื่อตัวแปรเป็นไทย/อังกฤษก็ได้ ห้ามขึ้นต้นด้วยตัวเลข และห้ามมีช่องว่าง
- ตัวแปร**เริ่มใหม่ทุกครั้งที่เริ่มเล่น** (กด START/REPEAT รอบใหม่ = ล้างค่า)
- พิมพ์ชื่อผิด เช่น `{รอบ2}` โปรแกรมคง `{รอบ2}` เดิมไว้ให้เห็น ไม่เดาค่าเอง

### 12.2 คลิปบอร์ด (Set Clipboard / Read Clipboard) (v1.20+)

| Action | Additional | ทำอะไร |
|---|---|---|
| **Set Clipboard** | ข้อความ (ใช้ `{ตัวแปร}` ได้) | ใส่ข้อความลงคลิปบอร์ด — วางต่อในแอปอื่นด้วย Ctrl+V ได้เลย |
| **Read Clipboard** | ชื่อตัวแปร เช่น `mytext` | อ่านคลิปบอร์ดปัจจุบันเก็บไว้ใน `{mytext}` |

ใช้ร่วมกันเป็นเวิร์กโฟลว์ได้ เช่น: Read Clipboard `code` → Image Click ปุ่มช่องกรอก →
Type Text `{code}` (วางข้อความที่คัดลอกไว้จากที่อื่นเร็วกว่าพิมพ์เอง)
— หมายเหตุ: Set Clipboard **เขียนทับ**คลิปบอร์ดเดิมของคุณ

### 12.3 ผูกกับปลั๊กอิน (v1.20+)

ปลั๊กอินที่มีลูปยาว ควรเรียก `ctx["stop_check"]()` เป็นระยะ — ผู้ใช้กด STOP แล้ว
plugin จะออกเอง และรายงานสถานะด้วย `ctx["ui"]["msg"]("ข้อความ")` — ดูตัวอย่างเต็ม
ที่ `plugins/README.md`

## บทที่ 14 — เชิงลึก v2.10: Dry-run · ผลเงื่อนไขเป็นตัวแปร · Batch runner

### 14.1 Dry-run — ซ้อมก่อนเล่นจริง (v2.10.1 มีรายงานไฟล์)

หลักการ: เดินสคริปต์ "จริงทุกอย่างยกเว้น input" — เงื่อนไข/บล็อก/ดีเลย์/ตัวแปรคำนวณจริงทุก
เส้นทาง แต่แถว input จริง (คลิก/กดคีย์/พิมพ์/เปิดแอป/คลิปบอร์ด) ถูกแทนด้วยข้อความ
"DRY-RUN: จะ…" แทนทำจริง — เมาส์/คีย์ไม่ขยับแม้ครั้งเดียว

ใช้เมื่อไหร่:
- สคริปต์เงื่อนไขซ้อนหลายชั้น อยากรู้ว่าถึงเวลาจริงจะเดินเส้นทางไหน
- ก่อนปล่อยงานค้างคืน (schedule/watchdog) — ซ้อมก่อนทุกรอบ ไม่เสี่ยงคลิกผิดตอนหลับ

วิธีใช้: เมนู **🧪 Dry-run** (GUI) หรือ `py auto_macro.py script.json --dry-run` (CLI)

**ใหม่ v2.10.1 — รายงานเป็นไฟล์:** จบ dry-run แล้วโปรแกรมเขียนสำเนาทั้งเส้นทางลง
`dry_report_วันที่.txt` ข้างโปรแกรม พร้อมสรุปนับรายการที่จะทำจริง — เหมาะกับงานยาว/จอเล็ก
อ่านย้อนหลังได้ (ถูกหยุดกลางคันก็บันทึกส่วนที่เดินผ่าน + ระบุว่า "ถูกหยุดกลางคัน")

```
===== DRY-RUN 21:33:05 — งานเช้า.json =====
สคริปต์: งานเช้า.json · แถวที่จะเล่น: 14 · รอบ: 1
DRY-RUN: จะคลิก Left Click 320,540
DRY-RUN: จะพิมพ์ Type Text สวัสดี
สรุปจะทำจริง: Left Click ×2, Type Text ×1, Beep ×1
===== จบรายงาน Dry-run =====
```

ข้อควรรู้:
- Wait for Image / Wait for Pixel จะ "รายงานทันทีไม่รอจริง" — dry-run จบเร็วเสมอ
- plugin ถูกแจ้งแทนรันจริง (แถว plugin ไม่ถูกเรียก) · รายงานเขียนทน error ทุกจุด —
  เขียนไม่ได้โปรแกรมไม่พัง แค่ไม่มีไฟล์ให้อ่าน
- หัวข้อหน้าต่างขึ้น [ DRY-RUN ] ตลอดการเล่น — จบเองหรือกด STOP ก็คืนโหมดเล่นจริงให้เอง

### 14.2 ผลเงื่อนไขเป็นตัวแปร — โทเคน `>ชื่อ`

ทุกแถวเงื่อนไข (If Image / If Pixel Color / If Variable / If Loop / If Time) เติม `>ชื่อ`
ท้าย Additional ได้ — ผลเงื่อนไข "1" (จริง) / "0" (ไม่จริง) ถูกเก็บลงตัวแปรชื่อนั้น
แล้วแถวถัดไปอ่านต่อได้ทันที (ห่วงโซ่เงื่อนไขโดยไม่เพิ่ม action ใหม่)

| แถวเงื่อนไข | Additional | ผลที่ได้ |
|---|---|---|
| If Image | `ปุ่มเขียว.png >เจอ` | เจอ → `{เจอ}`=1, ไม่เจอ → `{เจอ}`=0 |
| If Pixel Color | `300,300 #ffffff >สีตรง` | สีตรง → `{สีตรง}`=1 |
| If Variable | `n > 3 >พ้นเกณฑ์` | n>3 → `{พ้นเกณฑ์}`=1 |
| If Loop | `10 >ครบ 10 รอบ` | รอบ ≥ 10 → `{ครบ 10 รอบ}`=1 |

ต่อยอดในแถวถัดไป:
- **If Variable** แยกเส้นทางต่อ — `เจอ = 1` จริงเล่นต่อ / ไม่จริงข้าม N แถว
- **Block Start** ครอบทั้งก้อน — เงื่อนไขหัวบล็อกเขียน `if เจอ = 1` ได้เลย
- **ข้อความ** อ้างผลได้ เช่น Type Text `ผลตรวจ: {เจอ}` หรือ Write Log (plugin)

⚠️ ข้อควรระวัง:
- ชื่อห้ามเป็นคำ `on` / `of` / `and` (กันพิมพ์ `switch on` แล้วโดนตีเป็นชื่อตัวแปร)
- โทเคนถูกตัดออกจากเงื่อนไขก่อนค้นภาพ — `img.png >เจอ` ค้นหาไฟล์ `img.png` ไม่ใช่ชื่อเต็ม
- ตัวแปรเริ่มใหม่ทุกครั้งที่เริ่มเล่น (กฎเดียวกับตัวแปรทั่วไป — ดูบทที่ 12)

### 14.3 Batch runner — `--queue` + ปุ่ม 🗂️ Queue Bat (v2.10.1)

ไม่เล่นสักแถว) · จบไฟล์ไหนไปไฟล์ถัดไปทันทีไม่รอกดคีย์ · ท้ายโปรแกรมสรุปผลรายไฟล์

### แบบฝึกหัด (ทำตามได้จริง — ปลอดภัย ไม่คลิกอะไรบนจอ)

1. **ซ้อม dry-run:** เปิด `examples/14_dry_run_cond_vars.json` → เมนู 🧪 Dry-run →

   → รอบ 1–2: บี๊บแรกเล่น บี๊บหลังโดนข้าม ({ครบ} ยังเป็น 0) · รอบ 3: บี๊บแรกโดนข้าม

4. **เก็บถาวรครั้งแรก:** เปิดหลาย ๆ วันแล้วเล่นสคริปต์ทิ้ง log ไว้ → เมนู 📝 Log →

## บทที่ 16 — ผู้เล่นคิวแบบ GUI (v2.12): เล่นหลายไฟล์ในโปรแกรม ติดตามผลสด

บทที่ 14 ใช้ CLI `--queue` / ปุ่ม 🗂️ Queue Bat รันคิวผ่านคอนโซล — v2.12 เพิ่มเมนู
**📑 Run Queue** ให้เล่นคิวในโปรแกรมเลย เห็นผลทุกไฟล์แบบสด ไม่ต้องเปิดคอนโซล

### 16.1 เริ่มเล่นคิว
1. เตรียมไฟล์ลิสต์ `.txt` รูปแบบเดิม (บรรทัดละพาธสคริปต์ ข้าม `#` และบรรทัดว่าง
   พาธสัมพัทธ์อิงโฟลเดอร์ของลิสต์) — ใช้ลิสต์เดียวกับ `--queue`/Queue Bat ได้เลย
2. กดเมนู 📑 Run Queue → เลือกไฟล์ลิสต์ → หน้าต่างแสดงรายชื่อไฟล์ทั้งหมด (สถานะ "รอเล่น")
3. กด **▶ เริ่มเล่นคิว** — โปรแกรมตรวจทุกไฟล์ก่อน (ไฟล์พัง = ยกเลิกทั้งคิว ไม่เล่นสักแถว
   เหมือน CLI) แล้วเล่นทีละไฟล์: แถวกำลังเล่นเป็นสีน้ำเงิน ป้ายด้านบนบอกไฟล์ปัจจุบัน
   กล่องด้านล่างแสดงผลลัพธ์ของ CLI แบบทันที (เก็บ 200 บรรทัดล่าสุด)

### 16.2 สถานะรายไฟล์
| สถานะ | ความหมาย |
|---|---|
| กำลังเล่น… (น้ำเงิน) | ไฟล์นี้กำลังเดินอยู่ |
| จบครบ ✔ (เขียว) | เล่นจบเองครบทุกแถว |
| ถูกหยุด (ส้ม) | ถูกสั่งหยุดกลางคัน |
| พบปัญหา (exit N) (แดง) | ไฟล์จบด้วยปัญหา — คิวยังเล่นไฟล์ถัดไปต่อ |
| ตรวจไม่ผ่าน / ไม่พบไฟล์ (แดง) | ตรวจก่อนเล่นไม่ผ่าน — ยกเลิกทั้งคิว |
| — (ยกเลิก) (เทา) | ไฟล์นี้ถูกข้ามเพราะหยุดทั้งคิว |

### 16.3 หยุด 2 ระดับ
- **⏹ หยุดไฟล์นี้** — หยุดไฟล์ปัจจุบันแล้ว**เล่นไฟล์ถัดไปต่อ** (ใช้กลไก `--stop-file` ของ
  CLI โดยสร้าง stop-file ของไฟล์นั้นโดยเฉพาะ — ไฟล์อื่นไม่ถูกกระทบ)
- **⏹⏹ หยุดทั้งคิว** — หยุดไฟล์ปัจจุบัน + ยกเลิกไฟล์ที่เหลือทั้งหมด
- **F8/Esc ระหว่างเล่น = หยุดทั้งคิว** — ความหมายเดียวกับ CLI `--queue` เดิม อย่าสับสน
  กับปุ่มหยุดไฟล์นี้

เกร็ด: จบคิวแล้วกด ▶ เริ่มใหม่ได้เลย (สถานะทุกแถวรีเซ็ต) · ปิดหน้าต่างขณะเล่น = โปรแกรม
ถามก่อนแล้วหยุดทั้งคิวให้ · ปิดโปรแกรมขณะเล่น = สั่งหยุดทั้งคิวอัตโนมัติ · คิวทำงานบนเธรดแยก
ผ่าน CLI จริงทุกโลจิก — ระหว่างเล่นคิวยังแก้ตาราง/โหลดสคริปต์อื่นได้ตามปกติ

### แบบฝึกหัด 16
1. สร้างสคริปต์ 2 ไฟล์ (แถว Beep ล้วนก็พอ) + `list.txt` แล้วเล่นผ่าน 📑 Run Queue —
   สังเกตสถานะเปลี่ยนจาก "รอเล่น" → "กำลังเล่น…" → "จบครบ ✔"
2. ระหว่างคิวกำลังเล่น กด **⏹ หยุดไฟล์นี้** — ตรวจว่าไฟล์แรกขึ้น "ถูกหยุด" แต่ไฟล์ที่สอง

## บทที่ 17 — Plugin API v3: เงื่อนไขของคุณเอง (v2.13)

บทนี้ต่อจาก Custom Action (v1.16) — นอกจากเขียน plugin เป็น **Action** ได้แล้ว ตอนนี้
เขียนเป็น **เงื่อนไข** ได้ด้วย ใช้แทน/คู่กับ If Image/If Variable ในจุดที่เงื่อนไขในตัวยังทำไม่ได้

### 17.1 ประกาศเงื่อนไขใน plugin
ไฟล์เดิมประกาศ `ACTION_NAME` + `run(ctx, row)` — ตัวเงื่อนไขประกาศอีกคู่:

```python
# plugins/file_exists.py (แจกมากับโปรแกรม — ตัวอย่างจริง)
import os

CONDITION_NAME = "File Exists"

def check(ctx, row):
    """คืน True/False — ห้าม raise · อย่าแตะเมาส์/คีย์ (dry-run เรียก check จริง)"""
    try:
        path = str(row.get("additional") or "").strip()
        return bool(path) and os.path.isfile(path)
    except Exception:
        return False
```

กติกาเดียวกับเงื่อนไขทุกชนิด: **จริง = เล่นต่อ · ไม่จริง = ข้าม N แถว (N = คอลัมน์ Repeat)** ·
ไฟล์เดียวมีทั้ง ACTION_NAME และ CONDITION_NAME ได้ (ชื่อต้องต่างกัน) · ชื่อห้ามชน Action เดิม
และ plugin อื่น (ไฟล์ที่ชนถูกข้ามพร้อมสาเหตุ — ดูได้จาก `load_plugins.last_failed`)

### 17.2 ใช้ในสคริปต์ 2 ทาง
1. **คอลัมน์ Action** — ดับเบิลคลิกช่อง Action เลือกชื่อเงื่อนไข (dropdown เพิ่มให้อัตโนมัติ)
   ช่อง Additional = อาร์กิวเมนต์ของเงื่อนไข (ใช้ `{ตัวแปร}` ได้ — ถูกแทนค่าก่อนส่งเข้า `check`)
   และใส่ `>ชื่อ` ท้ายแถวเพื่อเก็บผล "1"/"0" ลงตัวแปรเหมือนเงื่อนไขในตัว
2. **Block Start/End** — Additional ของ Block Start เขียน `if File Exists C:\\work\\done.flag`
   (ผสม `&&` กับเงื่อนไขอื่นได้ เช่น `if File Exists f.txt && n > 3`) — เงื่อนไขไม่จริง = ข้ามทั้งบล็อก

### 17.3 ข้อควรรู้
- **ตรวจสคริปต์ครบ** — 🔍 Validate / `--validate` / ตรวจตอน START รู้จักชื่อเงื่อนไข plugin แล้ว
- **Dry-run เดินจริง** — เงื่อนไขเดินจริงอยู่แล้ว (บทที่ 14) → `check` ถูกเรียกจริง จึงควรเขียน
  ให้เป็น "อ่านอย่างเดียว" (อ่านไฟล์/สีจอ/ตัวแปร — ห้ามคลิก/พิมพ์)
- **.ahk** — แถวเงื่อนไขและบล็อกที่อ้างเงื่อนไข plugin ถูก export เป็น comment ทั้งบล็อก
  (AHK แปลไม่ได้ — จัดบล็อกเองใน .ahk)
- คู่มือเต็ม + เกณฑ์ส่ง plugin ชุมชน: [PLUGINS.md](PLUGINS.md) · ตัวอย่าง: `examples/14_condition_plugin.json`

### แบบฝึกหัด 17
1. เปิด `examples/14_condition_plugin.json` แล้วเล่น — สังเกตว่าแถว File Exists ที่ชี้ไฟล์
   "ไม่มีจริง.txt" ข้าม Beep แถวถัดไปไป 1 แถว (Repeat = 1)
2. เขียน plugin เงื่อนไขของคุณ เช่น `CONDITION_NAME = "After 6pm"` + `check` ที่เทียบ
   `time.localtime()` — ใส่ใน Block Start เป็น `if After 6pm` แล้วลองทั้งตอนเช้า/ค่ำ
3. สร้างไฟล์ที่ชื่อซ้ำ (เช่น CONDITION_NAME = "Left Click") แล้วรีสตาร์ต — ตรวจว่าโปรแกรม
   ยังเปิดได้ปกติ และชื่อที่ชนไม่โผล่ใน dropdown

## บทที่ 18 — เงื่อนไข plugin สำเร็จรูป + 🧩 + --dry-report (v2.14)

### 18.1 เงื่อนไข 4 ตัวที่มากับโปรแกรม

ตอนนี้โฟลเดอร์ `plugins/` มีเงื่อนไขพร้อมใช้แล้ว 4 ตัว — ใช้เป็น Action หรือใน Block Start ได้ทันที:

| เงื่อนไข | Additional | จริงเมื่อ |
|---|---|---|
| `File Exists` | พาธไฟล์ | ไฟล์มีจริง |
| `Internet Up` | (ว่าง) หรือ `host[:port]` และ/หรือ `Ns` | เชื่อม TCP สำเร็จ (ค่าเริ่มต้น 1.1.1.1:443 รอ 2 วิ) |
| `Process Running` | ชื่อโปรเซส เช่น `chrome` | มีโปรเซสรันอยู่ (tasklist/pgrep) |
| `Window Exists` | ข้อความในชื่อหน้าต่าง เช่น `Notepad` | มีหน้าต่างที่ชื่อตรงเปิดอยู่ |

ตัวอย่าง Block Start ผสมได้: `if Internet Up && Process Running chrome` — เน็ตขึ้นและ Chrome
รันอยู่เท่านั้นถึงจะเล่นบล็อก · OS ที่ไม่มีเครื่องมือ (เช่น ไม่มี xdotool) = เท็จ โปรแกรมไม่พัง

### 18.2 ปุ่ม 🧩 แทรกแถวเงื่อนไขให้

เมื่อโหลด plugin เงื่อนไขแล้ว แถบเครื่องมือจะมีปุ่ม **🧩 เงื่อนไข plugin** — เลือกชื่อจาก dropdown
+ พิมพ์อาร์กิวเมนต์ กด "แทรก" ได้แถวใหม่ใต้แถวที่เลือก (Repeat = จำนวนแถวที่ข้ามเมื่อเงื่อนไขไม่จริง
แก้ทีหลังได้) · Ctrl+Z ย้อนได้ · ไม่มี plugin เงื่อนไข = ปุ่มไม่โผล่

### 18.3 CLI --dry-report PATH

`--dry-run` เขียนรายงานลง `dry_report_วันที่.txt` ข้างโปรแกรมเสมอ (v2.10.1) — ตอนนี้เลือกที่เองได้:

```bash
py auto_macro.py script.json --dry-run --dry-report C:\reports\night_{date}.txt
```

- `{date}` = วันที่วันนี้ (เช่น `night_2026-10-05.txt`) — ใช้กับงานค้างคืนรายวันได้เลย
- เขียน **ต่อท้ายไฟล์เดิม** (แต่ละรอบ = บล็อกใหม่คั่นบรรทัดว่าง)
- ใช้กับ `--dry-run` เท่านั้น — ลำพัง = โปรแกรมเตือนแล้วเล่นปกติ
- เมนู 🧪 Dry-run ในโปรแกรมก็เลือกพาธได้ (ช่องพาธ + ปุ่มเลือกไฟล์ — จำไว้จนปิดโปรแกรม)

ตัวอย่างครบทุกเงื่อนไขในบทนี้: `examples/15_system_conditions.json`

## บทที่ 19 — เล่นเฉพาะกลุ่มหัวข้อ (v2.15)

### 19.1 คลิกขวาที่หัวข้อ → "▶ เล่นกลุ่มนี้อย่างเดียว"

สคริปต์ยาวที่แบ่งเป็นขั้น ๆ ด้วยหัวข้อ Section (⬛) ทดสอบ/รันทีละกลุ่มได้แล้ว:
**คลิกขวาที่แถวหัวข้อ → ▶ เล่นกลุ่มนี้อย่างเดียว** — โปรแกรมเล่นเฉพาะแถวที่เปิดใช้ (☑) ในกลุ่มนั้น
จนถึงหัวข้อถัดไป แล้วหยุดเอง ไม่ต้องปิดแถวอื่นเอง

- ผ่าน **player จริงสายเดียวกับ START ทุกอย่าง** — validate/STOP (F8)/ไฮไลต์แถว/log/เลขรอบ ครบ
- **แถวในกลุ่มที่ย่ออยู่ก็เล่นครบ** — ย่อกลุ่มไว้ประหยัดจอแล้วเล่นได้ปกติ (สัญญาเดียวกับ v1.22)
- กลุ่มไม่มีแถวที่เปิดใช้ = เตือน statusbar "กลุ่มนี้ไม่มีแถวที่เปิดใช้" แล้วจบเงียบ ไม่เริ่มเล่น

แบบฝึกหัด: สร้างสคริปต์ 3 กลุ่ม (เตรียม/งาน/ล้าง) แต่ละกลุ่มใส่ Beep 2 แถว → คลิกขวาหัวข้อ "งาน"
→ เลือกเล่นกลุ่มนี้อย่างเดียว → ได้ยินเฉพาะ B1, B2

### 19.2 CLI --only-section ชื่อ

```bash
py auto_macro.py script.json --only-section งาน
```

- หาหัวข้อชื่อตรงเป๊ะ (ตัวพิมพ์สำคัญ) — print ช่วงแถว + จำนวนที่จะเล่นแล้วเล่นเฉพาะกลุ่มนั้น
- ชื่อไม่พบ = เตือน "ไม่พบหัวข้อชื่อ 'งาน'" แล้ว**เล่นทั้งหมด**ตามปกติ (ไม่มีวันเล่นว่างเงียบ ๆ)
- สายเดียวกับเล่นทั้งหมด — validate/STOP/`--max-minutes`/log [SKIP] ทำงานครบ เอาไปผสม
  `--queue`/watchdog ได้เลย เช่น รันคิวที่แต่ละไฟล์เล่นเฉพาะกลุ่มของตัวเอง

### 19.3 ย้ายกลุ่มทั้งก้อน (v2.15.1 — Group order)

ลำดับกลุ่มผิดที่? ไม่ต้องลากทีละแถว — **คลิกขวาที่หัวข้อ → "⬆ ย้ายกลุ่มขึ้น" / "⬇ ย้ายกลุ่มลง"**
สลับก้อน [หัวข้อ + แถว + แถวย่อใน stash] กับกลุ่มข้างเคียงทั้งก้อนในครั้งเดียว
(หรือคลิกหัวข้อแล้วกด **Alt+↑/↓** หรือปุ่ม ▲▼ ก็ได้ผลเดียวกัน)

- แถวย่อใน stash เดินตามหัวข้อของตัวเองเสมอ — ย่อกลุ่มไว้แล้วย้าย แถวไม่หลุดกลุ่ม
- Block Start/End คร่อมกลุ่ม (Start ในกลุ่มหนึ่ง End อีกกลุ่ม) = ปฏิเสธพร้อมเตือน กันบล็อกพัง
- ย้ายผิดกด **Ctrl+Z** ย้อนได้ · กลุ่มแรกขึ้นบน/กลุ่มสุดท้ายลงล่าง = ไม่มีผล

แบบฝึกหัด: สร้างกลุ่ม A/B/C แล้วกด "⬆ ย้ายกลุ่มขึ้น" ที่ B สองครั้ง → ลำดับกลายเป็น B, A, C —
แล้วกด Ctrl+Z กลับเป็น A, B, C

## บทที่ 20 — Launcher คู่สคริปต์ · ไทม์ไลน์เหตุการณ์ · เงื่อนไข plugin ชุมชน (v2.16)

### 20.1 🚀 Launcher คู่สคริปต์ — ดับเบิลคลิก = เล่นสคริปต์ทันที (Issue #3)

งานที่รันซ้ำทุกวัน (backup ร้าน, ป้อนข้อมูล, เข้าเกม) ไม่ต้องเปิดโปรแกรมหลักอีกต่อไป:

1. จัดสคริปต์ให้เรียบร้อยแล้วกด **💾 Save**
2. กดเมนู **🚀 Launcher** — โปรแกรมสร้างไฟล์คู่ข้างสคริปต์:
   - `ชื่อสคริปต์.bat` — launcher ที่เลือกเส้นทางให้เอง: มี `AutoMouseMacro.exe` ในโฟลเดอร์เดียวกัน =
     เปิด exe ไปเลย (หน้าต่างดำหายไปเอง), ไม่มี = รอง `py auto_macro.py` + pause ให้เห็น error
   - `ชื่อสคริปต์.lnk` (Windows) — มี exe = ชี้ตรง exe (ได้ไอคอนโปรแกรม สะอาดสุด), ไม่มี = ชี้ .bat แทน
3. **ดับเบิลคลิก .lnk (หรือ .bat)** = เล่นสคริปต์นั้นทันที

- ส่งอาร์กิวเมนต์เพิ่มได้ — คลิกขวา .bat → แก้ไข → เติมท้ายบรรทัด เช่น `--loop --speed 2`
  (ลิสต์เต็ม: `py auto_macro.py --help`)
- ปุ่มนี้เสริมของเดิม: 📤 Export Bat (สร้าง .bat/.sh ข้างสคริปต์) และ 🗂️ Queue Bat (คู่ไฟล์ลิสต์คิว)
- .lnk ต้องใช้ PowerShell (มีเฉพาะ Windows) — OS อื่นจะได้ .bat/.sh อย่างเดียว ใช้งานได้เหมือนกัน

แบบฝึกหัด: Save สคริปต์ Beep 2 แถวชื่อ `เช้า.json` → 🚀 Launcher → ดับเบิลคลิก `เช้า.lnk`
→ ได้ยินบี๊บ 2 ครั้งโดยไม่ต้องแตะโปรแกรมหลักเลย

### 20.2 ⏱ ไทม์ไลน์เหตุการณ์ — ดีบั๊กเงื่อนไขซ้อนหลายชั้น (Issue #4)

สคริปต์ที่ใช้ If Image/If Variable/Block Start ซ้อนหลายชั้น บางทีอยากรู้ว่า "รอบล่าสุดเกิดอะไรขึ้น"
— เปิด **📝 Log → ปุ่ม ⏱ ไทม์ไลน์การเล่นล่าสุด**:

- ตารางแต่ละแถว = 1 เหตุการณ์: **เวลา · ผล (▶ เล่น / ⏭ ข้าม / ℹ อื่น ๆ) · แถว i/N · เหตุการณ์ · วินาที**
  สีเขียว = เล่นจริง, ส้ม = ถูกข้าม (เหตุผลอยู่ในคอลัมน์เหตุการณ์ เช่น `If Loop · ข้าม 2 แถว`), เทา = ข้อมูลระบบ
- **dropdown "การเล่น:"** ย้อนดูได้ทุกครั้งที่เล่นวันนี้ — หัวข้อบอกสรุป
  `13:02:11 — demo.json (เล่น 12 · ข้าม 3)` · เปิดมาชี้รายการล่าสุดให้เอง
- ข้อมูลมาจาก log เดิมทั้งหมด (`parse_log_timeline` ใน engine) — เปิด/ปิด log ใน Settings ได้เหมือนเดิม
  ถ้าปิด log ไว้ ไทม์ไลน์จะไม่มีข้อมูล (ไฟล์ log คือแหล่งข้อมูลเดียว)

แบบฝึกหัด: สคริปต์ If Loop ข้าม 1 แถว + Beep เล่น 1 รอบ → เปิดไทม์ไลน์ → เห็นแถว If Loop เป็นส้ม
"ข้าม 1 แถว" และ Beep เป็นเขียว

### 20.3 🔌 เงื่อนไข plugin ชุมชนรอบใหม่ (Issue #5)

3 เงื่อนไขใหม่แถกมากับโปรแกรม (ใช้เหมือนเงื่อนไข plugin ทุกกติกา — Action หรือ Block Start `&&`,
ใช้ `{ตัวแปร}` ได้, ไม่เพิ่ม dependency):

| เงื่อนไข | Additional | จริงเมื่อ |
|---|---|---|
| **Window Focused** | ข้อความในชื่อหน้าต่าง เช่น `งานเอกสาร` | หน้าต่างที่**โฟกัสอยู่ตอนนี้**มีข้อความนั้น (ต่างจาก Window Exists ที่สแกนทุกหน้าต่าง) |
| **File Newer Than** | `report.csv > done.flag` หรือ `setup.zip 60s` | ไฟล์แรกใหม่กว่าไฟล์ที่สอง / ไฟล์ถูกแก้ภายใน N วินาทีล่าสุด |
| **HTTP Status** | `https://api.local/health 200 3s` | URL ตอบรหัสที่ต้องการ (ไม่ใส่รหัส = 2xx ใด ๆ; `3s` = รอสูงสุด 3 วิ) |

ตัวอย่างใช้งานจริง: ก่อนเริ่มงานหลัก ใส่ Block Start `if HTTP Status https://api.local/health 200 &&
Process Running chrome` — API ล่มหรือเบราว์เซอร์ไม่เปิด = ข้ามกลุ่มงานนั้นทั้งหมด

แบบฝึกหัด: สร้างไฟล์ `a.txt` + `b.txt` แก้ a.txt ทีหลัง → แถว File Newer Than `a.txt > b.txt`
→ จะเห็น "เงื่อนไขจริง เล่นต่อ" ใน console/log — แล้วกด ⏱ ไทม์ไลน์ดูผลในหน้าต่างเดียว
